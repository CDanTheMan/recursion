## Why the former broad milestone was split

The former schema list combined autonomous planning with routes, plugins, scientific records,
terminal protocol, persistence and publication. That made the first construction step too large
to falsify and obscured privileged-code ownership. M1A keeps only pure planning behavior. Inert
route/budget/lease/PAUSE/effect references remain solely to test the mandatory failure states;
they do not implement those subsystems.

- **M1B** is Owner-authorized as a bounded local campaign after M1A's merge. It adds inert route,
  plugin and process requirement contracts, still without a
  provider call, process launch or plugin execution. Its red fixtures should cover manifest-first
  no-import admission, full artifact/dependency digests, capability/policy intersection, stale
  reload fencing, daemon cursors/credit/input leases and zero-cost-disabled behavior described in
  [FRONTIER-HARNESS-EVIDENCE.md](FRONTIER-HARNESS-EVIDENCE.md).
- **M1C** is Owner-authorized as a bounded local campaign after M1B's merge. It adds inert
  source/effect/publication/persistence requirement contracts. SQLite, scientific
  adapters, Git, publication, external effects and migration remain later separately authorized
  work.

Post-M1A implementation choices remain experiments, not prerequisites: CPython/Rust/Go for the
same pure reducer/replay workload; JSONL versus SQLite metadata with identical artifacts; and typed
external-engine adapters versus a minimal native loop. Do not choose a production language, store,
wire format, plugin sandbox or renderer inside M1A.

The evidence-backed sequence after M1A contract freeze is:

1. translate the accepted contracts into the bounded TLA+/PlusCal model and retain counterexamples
   from deliberately removed authority, lease, amendment, PAUSE, retry, effect and verifier guards;
2. freeze identical `decode`, `admit`, `reduce` and `derive_work_packet` vectors, then compare
   CPython, Rust and Go on correctness/reproducibility floors before resources or speed;
3. compare JSONL/JSON Sequence plus CAS against SQLite WAL metadata plus the same CAS under the
   complete crash/corruption/disk-full/reader/migration matrix;
4. specify and fixture the terminal/process broker wire protocol before choosing renderer or
   process-library implementations;
5. admit plugin/frontend, cache/context and release work only after their disabled-path,
   capability, privacy and adapter-free boot fixtures exist; and
6. run the corrected sealed-corpus harness attribution study only after blinded power simulation
   establishes a unique-task count or explicitly labels the result exploratory.
