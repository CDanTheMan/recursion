## Consequential corrections

The 80 primary-source records and 24 registered conclusions in [evidence.json](evidence.json)
contain exact locators, versions/digests, applicability limits, contradictory evidence and
decisive tests. Historical sources and answer capture were preserved.

- Muse Code is Meta's terminal beta. Grok Build and Grok Bot are different products.
  Antigravity local SDK and managed API are different routes. Cursor first-party SDK/ACP,
  independent ACP adaptation and Cursor BYOK must not be conflated. MKR-001/MKR-007.
- Rich interfaces change the control picture. Cursor local SDK steering differs from cloud
  follow-up; Grok native question/compaction extensions and internal buffered interjection
  exceed a basic CLI; Gemini core compression and OpenCode questions offer adaptation paths.
  Internal code still does not certify a supported wire contract. MKR-003/MKR-023/MKR-024.
- Permission surfaces are incomplete enforcement boundaries. Grok hooks generally fail open;
  the independent Cursor adapter may retry a whole turn without autoReview; Claude context
  ingestion can bypass an assumed tool hook. Scope/epoch/resource enforcement stays outside
  those hooks. MKR-004/MKR-006/MKR-011/MKR-023.
- Upstream-only means every reasoning/helper role is eligible and accounted. Hermes auxiliary
  routing and Claude classifier/token-count exclusions defeat simplistic main-model accounting.
  ChatGPT sign-in documents Codex use, not general native API entitlement. MKR-002/MKR-005/MKR-024.
- Stop acknowledgment, conversation fork and executable rollback are narrower than the required
  outcomes. Preserve external uncertainty, original dirty work, current history and cumulative
  reservations. No provider reset or repeated failure creates a fresh recovery budget.
  MKR-011/MKR-012/MKR-015/MKR-016.
- Cache, larger context, persistent processes and more supervisors remain value hypotheses.
  Count failed work, cache writes, compaction, verification, recovery and human correction.
  Match resource guarantees and ceilings; missing denominators stay unavailable. MKR-019/MKR-020.

## What is established and what is not

Established: completed Owner requirements; preserved repository ancestry and historical inputs;
source-documented mechanisms, interfaces and their limitations; local validation of existing
inert regression entrypoints. Final candidate gate/review results are external receipts.

Proposed: assistant identity projection, bounded consultation, control receipts and fork capture,
configuration revision semantics, no-effect incompatibility response, six-mode update transitions,
failure-specific recovery and cumulative componentwise recovery budgets.

Unproven: live route eligibility or integration, full control parity, hidden-helper budget bounds,
semantic preservation under failures, minimum hardware, optimal verification presets, performance
wins and safe release/migration. A source digest, package license or synthetic validator cannot
establish those properties.
