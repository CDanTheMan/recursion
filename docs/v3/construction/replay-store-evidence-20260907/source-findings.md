Its [Windows replace path](https://github.com/python/cpython/blob/0cc81280367df838c4b199f8f0378837165071c2/Modules/posixmodule.c#L5536) uses MoveFileExW with MOVEFILE_REPLACE_EXISTING, without WRITE_THROUGH. The subprocess [termination path](https://github.com/python/cpython/blob/0cc81280367df838c4b199f8f0378837165071c2/Lib/subprocess.py#L1673) uses the retained process handle; kill aliases terminate. The parent must wait for exit before admitting a fresh reader. This covers an owned direct helper, not descendant-tree termination.

Microsoft documents [MoveFileExW flags](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw), [_commit](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/commit?view=msvc-170) and [TerminateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess). Explicit flush and a completed process wait justify this local process-cut method. They do not turn it into a power-loss, device-cache or directory-entry durability test. CPython is used as existing local probe tooling under its PSF license; no runtime/framework selection follows. No upstream implementation code is copied into the probe.
