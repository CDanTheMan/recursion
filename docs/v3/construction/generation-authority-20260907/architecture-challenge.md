# Architecture challenge across execution arms, 2026-09-07

The Owner requested deeper cross-repository architecture research before the next construction. Four bounded read-only packets examined activation, durable consultation, execution arms and memory/cache behavior; Astra integrated the findings. [Owner steering](owner-steering.json) records the widened discovery team while preserving the deadline and operational limits. This addendum challenges and extends the existing [three-arrangement comparison](../../foundation-research/mark2-research/mark3-comparison/architectures.md); it does not replace canonical contracts or select a framework.

The research opportunity is a coherent cross-harness contract for authority, continuity and accounting. These mechanisms have substantial prior art. No novel general algorithm, superior harness or task-performance result is claimed. The new value is identifying combinations that fail despite their individual components behaving as documented, and specifying the additional boundary Recursion would need.

## Three complete competing arrangements

| Capability | A: demand-activated role services | B: resident specialist hub | C: durable coordination assistance |
| --- | --- | --- | --- |
| Authority and canonical state | One deterministic writer admits goals, grants, dispatch and evidence adoption. | Same writer; hub state is a replaceable session/projection layer. | Same writer; workflow history is scheduling evidence, never an independent grant authority. |
| Execution arms | Broker-owned native or supported upstream sessions for each reasoning role; rehydrate persistent identity on demand. | Warm bounded sessions or harness subsessions; each child incarnation has its own authority and meter segment. | Admitted activities invoke those same native/upstream routes; a durable wait does not require a model to remain running. |
| Configuration/plugins | Prepare an immutable dependency closure; activate eligible isolated workers lazily. Optional pure components receive explicit bytes/imports. | Trusted dynamic registry and pools; guarded handles plus invocation accounting are separate from service registration/use counts. | Exact configuration/authority identities travel with workflow inputs; revalidate before effect dispatch, not only on history replay. |
| Communication | Canonical received/adopted/rejected records plus direct consultation envelopes; optional durable transport carries them. | Shared routing and sessions, with partitioned principal/context/configuration state. | Workflow waits or invocation mailboxes manage progression; separate one-shot decisions from repeated steering and detached child effects. |
| Memory | Immutable evidence and branch manifests; demand reconstruction of disposable indexes. | Shared incremental indexes with explicit completeness/compaction boundaries; causal notebooks retain conflicts. | Same evidence/branch contract; durable waits refer to immutable evidence, not expiring cache entries. |
| Headroom/caching | Optional tool-output adapter, original retention and exact transform identity. | Same adapter; retained hosts and cross-session settings add isolation/idle costs. | Same adapter as an admitted operation; workflow completion cannot substitute for original availability. |
| Principal advantage to test | Lower retained lifecycle complexity and clearer zero-import disabled state. | Faster reuse of warm specialized context and indexes. | Simpler recovery of long waits and multi-step coordination. |
| Main cost/falsifier | Cold starts and repeated reconstruction may hurt responsiveness. | Mixed revisions, shared state, old handles and hidden counter resets may violate contracts. | Rejected commands, stale promises, duplicate retry owners and detached work can escape history-based accounting. |

All arrangements preserve Head, ARM, questionnaire assistant, planner, implementer, reviewer, summarizer and recovery roles with explicit eligible execution and parent accounting. Every role can use an admitted upstream route in an independently useful upstream-only configuration; no native model server or separate API planner becomes mandatory. Native and combined execution remain equally required. Ordinary status, timers, queue maintenance, Stop and reconciliation remain deterministic. Residency, durability, isolation, compression and cache reuse are independent configuration axes; compare them with other axes held constant.

Retain A as the first composition candidate, B as its responsiveness competitor, and C for a discriminating long-wait/lost-receipt case. This carries forward the original disposition, with stronger falsifiers. Reuse supported sessions, transports and optional algorithms. Adapt lifecycle/recovery semantics. Build only the missing common admission, provenance, incarnation accounting, adoption and effect-settlement boundary after its formal obligations are checked.

## New discriminators beyond the canonical baseline

**Activation must bind the dependency closure.** Existing CMP research distinguishes xDS ACK from application. The new [Envoy warming evidence](https://github.com/envoyproxy/envoy/blob/db4310bdf8e7b6dff5e0a4f7d583ce76cdf54b38/docs/root/api-docs/xds_protocol.rst) is more specific: routes do not warm like clusters/listeners, and route-before-cluster updates can blackhole requests. Individual resource readiness therefore cannot certify a coherent plugin/decoder/policy graph. Require an activation identity binding exact artifacts, schemas, configurations and retrieval/transform policies. Cached dependencies must match that identity. [Local TTL expiry](https://github.com/envoyproxy/envoy/blob/db4310bdf8e7b6dff5e0a4f7d583ce76cdf54b38/source/common/config/ttl.cc) is not settlement of already started work.

**Registry modification and quiescence are different contracts.** [OSGi DS1.5](https://docs.osgi.org/specification/osgi.cmpn/8.0.0/service.component.html) permits modification processing to continue after a callback throws, and separates enabled state from asynchronous activation. [Felix's component manager](https://github.com/apache/felix-dev/blob/534c4ae56aa7bc8fba857d85c0deb272b6d6ddc3/scr/src/main/java/org/apache/felix/scr/impl/manager/SingleComponentManager.java) uses a VOID failure default for modification and may continue dependency/property updates. Its service use count tracks acquisitions, not individual active calls. [OSGi Core8](https://docs.osgi.org/specification/osgi.core/8.0.0/framework.service.html) does not guarantee that an unregistered ordinary object stops functioning through retained references. Compare fresh-generation preparation with in-place callbacks; require guarded invocation handles and separate drainage/settlement receipts. These are adaptation requirements, not upstream specification violations.

**Guest interruption is not host-effect settlement.** The pinned [Wasmtime interruption contract](https://github.com/bytecodealliance/wasmtime/blob/668016926adfd1b8a79dbce894f1e203d8892599/crates/wasmtime/src/config.rs) cannot interrupt a guest blocked in a host call; the embedder must arrange cancellation/wakeup. Its [resource limiter](https://github.com/bytecodealliance/wasmtime/blob/668016926adfd1b8a79dbce894f1e203d8892599/crates/wasmtime/src/runtime/limits.rs) excludes some runtime/host allocations. Prefer pure transformations as the first component comparison. Effectful imports need current authority, whole-worker accounting and external outcome records even after a guest trap.

**Rejected consultation requires ingress provenance.** Temporal's [Update implementation](https://github.com/temporalio/sdk-go/blob/82c8087ecd03722e2b8e7c6c892784095fa94e73/internal/internal_update.go) distinguishes rejection from acceptance history, and its [message documentation](https://docs.temporal.io/develop/go/workflows/message-passing) explicitly excludes validator-rejected Updates from accepted history. A lost rejection reply cannot be recovered solely from that history. An attributable gateway record must retain command identity/digest, principal, expected revision and disposition under the privacy policy. Signal receipt is not processing; Continue-As-New also requires handler/channel drainage. This deepens the existing cooperative-cancellation comparison.

**Durable decisions need revision identity.** Restate's [SDK](https://github.com/restatedev/sdk-typescript/blob/6879b36b6774c580c8dad9812cc6088150909dae/packages/libs/restate-sdk/src/context_impl.ts) distinguishes signals from named promises. Current [external-event documentation](https://docs.restate.dev/develop/ts/external-events) differentiates repeatable steering from one-shot retained decisions. A reused promise named approval can return a result for an obsolete goal revision; durable delivery is not renewed authority. Bind decision/goal revision and recheck before adoption. Place long consultation waits outside short exclusive reservation-owner handlers. [One-way/delayed calls](https://docs.restate.dev/services/invocation/managing-invocations) can survive parent cancellation, so their reservations persist until separately settled. Exact SDK/server support for newly documented signals is unverified.

**Transport acknowledgment cannot fence a worker.** [JetStream's pinned consumer documentation](https://github.com/nats-io/nats.docs/blob/f115becf6563e3bbe16bb94cbf87bfceb84199c1/nats-concepts/jetstream/consumers.md) permits a late ACK after redelivery. The [server ACK path](https://github.com/nats-io/nats-server/blob/622457b6dfd5649fdc882cacb287528424762948/server/consumer.go) tracks transport pending state by stream sequence; it is not Recursion's current-attempt grant check. [Dedup IDs expire](https://github.com/nats-io/nats-server/blob/622457b6dfd5649fdc882cacb287528424762948/server/stream.go), with a two-minute default at this pin. Reuse transport flow control, but retain application operation identity, attempt fencing and unresolved effects beyond transport retention. This concretizes the existing RIFL/ambiguity requirement rather than claiming exactly-once external execution.

**Reusable specialists need incarnation accounting.** [OpenHands delegation](https://github.com/OpenHands/software-agent-sdk/blob/3896f186936342b99c7c5d3f89cdae888f458e7f/openhands-tools/openhands/tools/delegate/impl.py) resets child metrics at creation, permits replacement under a friendly ID and replaces that ID's cumulative parent metric entry. Replacement avoids repeat-report double counting within an incarnation; an adapter also needs retained prior incarnations. The same path can continue a pending-confirmation child when no handler is supplied, and [conversation execution](https://github.com/OpenHands/software-agent-sdk/blob/3896f186936342b99c7c5d3f89cdae888f458e7f/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py) treats a second run as confirmation. Inherited confirmation policy alone is insufficient evidence of Owner consent. These are source-supported adapter hypotheses, not reproduced upstream bugs.

**Separate histories do not isolate state or authorize merge.** [ADK Python's implementation](https://github.com/google/adk-python/blob/b0180620f4c2f4f4467a89c37a30f75bf849700b/src/google/adk/agents/parallel_agent.py) explicitly shares last-writer-wins session state across parallel branches despite separate histories. [Pinned public documentation](https://github.com/google/adk-docs/blob/4983b6974ae6b5414e82db9e9aa934064a3d5cdc/docs/agents/workflow-agents/parallel-agents.md) describes broader isolation; retain the contradiction and prefer the exact implementation for this build. Its per-branch yield/consume handshake is a useful bounded-producer candidate, but not a byte bound or settlement guarantee. ParallelAgent is deprecated at this pin; do not transfer its semantics to Workflow without inspection. Use immutable branch proposals and current-revision adoption, preserving rejected/contradictory advice for authorized review.

**A rich SDK still needs complete event and permission mapping.** [Claude SDK types](https://github.com/anthropics/claude-agent-sdk-python/blob/efd4d865ef1795daffee3cd24cce45307aed8a51/src/claude_agent_sdk/types.py) expose interleaved child attribution, task-updated terminal states without a task-notification event, and cumulative-total resets on conversation reset. Permission callbacks that cover prompted actions do not intercept every already-allowed tool; concurrent hook matchers cannot supply ordering authority. Its [fork forwarding](https://github.com/anthropics/claude-agent-sdk-python/blob/efd4d865ef1795daffee3cd24cce45307aed8a51/src/claude_agent_sdk/_internal/transport/subprocess_cli.py) supports transcript forks, not automatic grant inheritance. These richer surfaces deserve synthetic adapter fixtures before accepting CLI-wrapper limitations. SDK MIT licensing does not identify the required CLI build or certify distribution/account eligibility: compare the [third-party login restriction](https://code.claude.com/docs/en/agent-sdk/quickstart) with [subscription guidance](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), keeping personal use and product distribution distinct.

**Memory indexes are replaceable historical views.** Differential Dataflow's [trace contract](https://github.com/TimelyDataflow/differential-dataflow/blob/aa8745f93ea8abe131104fc7885ba4fd47e63902/differential-dataflow/src/trace/mod.rs) permits compaction to discard timestamp distinctions. Its [ordinary versus frontier import](https://github.com/TimelyDataflow/differential-dataflow/blob/aa8745f93ea8abe131104fc7885ba4fd47e63902/differential-dataflow/src/operators/arrange/agent.rs) distinguishes potentially partial intermediate histories from an explicit progress cut. Adapt shared arrangements only with completeness/retention contracts; process-local reference counting is not a durable distributed pin service. A lagging reader can retain history indefinitely. Compare demand reconstruction against incremental projection with global retained-byte and maintenance budgets.

**Convergence can hide disagreement.** Automerge's [read contract](https://github.com/automerge/automerge/blob/1618c976ca23fca8282c4a69ebbb0bb0c3f27ab1/rust/automerge/src/read.rs) chooses one deterministic conflicting value in get, while get_all exposes competing operations. Its [fork implementation](https://github.com/automerge/automerge/blob/1618c976ca23fca8282c4a69ebbb0bb0c3f27ab1/rust/automerge/src/automerge.rs) preserves causal heads, not authenticated principal authority. Consider causal notebooks for advice/annotations; adopt a conclusion through the canonical authority with exact heads/evidence. Never resolve an actual GoalSpec amendment by a CRDT winner. Old evidence may remain in a preserved fork while being ineligible for present disclosure.

**Fewer tokens need not mean more cache reuse.** vLLM's [prefix hash](https://github.com/vllm-project/vllm/blob/782f36cd0c7951cc1fa3c4fb3eeb916cc31780ed/vllm/v1/core/kv_cache_utils.py) chains earlier blocks, tokens and additional identities; changing an early compressed block changes downstream keys. Its [security guidance](https://github.com/vllm-project/vllm/blob/782f36cd0c7951cc1fa3c4fb3eeb916cc31780ed/docs/usage/security.md) qualifies the stronger [design wording](https://github.com/vllm-project/vllm/blob/782f36cd0c7951cc1fa3c4fb3eeb916cc31780ed/docs/design/prefix_caching.md): salting reduces sharing. A caller-supplied salt is not fresh authorization. The [plugin loader](https://github.com/vllm-project/vllm/blob/782f36cd0c7951cc1fa3c4fb3eeb916cc31780ed/vllm/plugins/__init__.py) also distinguishes general plugin loading from endpoint enablement. Conditional native-inference reuse must not create an upstream-only dependency.

## Bounded theoretical findings

The root committed [theory-plan.json](theory-plan.json) and the abstract checker before execution. [theory-evidence.json](theory-evidence.json) identifies that exact source and retained output. The initial 72-fixture run is retained as superseded after review corrected stale-ACK counting and exact rejection attribution. The corrected execution contains **75 closed abstract fixtures across nine discriminator groups**, including delayed recipient fencing. Each group rejects a selected shortcut, has no guarded violation in the declared abstraction and permits a selected positive outcome. Full rows and witness IDs are in [theory-results.json](theory-results.json). These are executable requirement examples and bounded shortcut counterexamples, not independent implementation proofs or runtime rankings.

| Discriminator | Shortcut counterexample | Guarded candidate obligation |
| --- | --- | --- |
| Activation closure | Advertise new revision despite old plugin behavior or unprepared dependency. | Admit only an exact prepared dependency set. |
| Revision-bound decision | Consume a retained revision1 approval after Owner revision2. | Current decision/revision check at adoption. |
| Detached settlement | Parent Stop removes reservation while accepted child remains unsettled. | Retain child consumption until separate settlement. |
| Stale transport ACK | Old worker ACK settles the redelivered current attempt. | Transport receipt and current-attempt effect receipt stay separate. |
| Incarnation accounting | Friendly-ID replacement overwrites an earlier cumulative segment. | Retain totals by incarnation; repeated reports replace only their own segment. |
| Branch adoption | Parallel proposal writes canonical decision directly. | Preserve proposals; adopt against the current base revision. |
| Memory freshness | Equal content hash bypasses branch, applied dependency counts, evidence eligibility or epoch check. | Historical cut and present disclosure authority are independently required. |
| Recipient fence installation | Delayed old permit launches after the recipient installs revocation. | Recheck installed recipient epoch; separately report admitted in-flight exposure before installation. |
| Rejected-command provenance | Lost rejection reply leaves no queryable history record. | Durable attributable ingress/disposition, under privacy bounds. |

These are constructed counterexamples to abstraction shortcuts, not observations of upstream runtimes. The applied dependency vector is not a Timely/Differential frontier mapping. The guards directly encode necessary conditions in this small domain; they do not establish feasibility, performance, malicious-caller resistance, distributed enforcement or composition. They are not a new implementation of the accepted full formal model and do not advance any of its 27 coverage rows. Callback internals, host-call cancellation, index compaction/fork retention and protocol hook races still require their specified probes.
