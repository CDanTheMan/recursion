## The question

How should the versioned wire protocol between thin terminal views, the `recursion` daemon and the managed process broker be fixed — transport, peer authentication, framing/versioning, cursors/resume, flow control, reconnect idempotency, process containment, the MCP/stdio bridge and the tool broker — before any renderer, multiplexer or IPC library is selected? The handoff requires this while preserving the detachable-terminal ruling (terminal bytes are data; attaching a view creates no actor/process/model/effect; a slow view cannot block the canonical writer), and explicitly forbids selecting a renderer, store, or serialization library and forbids claiming full descendant-tree termination before measurement.

## Key findings

- **Local transport (source-documented; disposition inferred).** Windows named pipes are the preferred Windows authority endpoint; pathname `AF_UNIX` stream sockets on Linux/BSD. Anonymous pipes, FIFOs, and loopback TCP cannot themselves prove a peer's user identity. Abstract `AF_UNIX` lacks a filesystem admission boundary and is rejected as default; loopback TCP is default-rejected or needs a real authenticated handshake (installation trust key + nonces/transcript binding), not "`127.0.0.1` means trusted."
- **Peer authentication (primitives source-documented; policy inferred).** Windows: explicit restrictive DACL + `PIPE_REJECT_REMOTE_CLIENTS` + successful named-pipe impersonation/token inspection; `GetNamedPipeClientProcessId` is correlation only, never the authentication root. Linux: private owner-controlled socket directory + `SO_PEERCRED` (with namespace qualifications for `SCM_CREDENTIALS`). BSD/macOS: private directory + `getpeereid` (effective UID/GID; portable PID unknown). All authenticate an OS principal, **not** a specific Recursion binary; same-UID hostile-process exclusion needs an additional key/attestation policy. Endpoint creation must refuse symlink/wrong-owner/stale endpoints rather than blind unlink.
- **Framing (design source-documented; operation unmeasured).** Four-byte unsigned big-endian length + one canonical M1B UTF-8 JCS/I-JSON object, `1 <= N <= 262,144` payload bytes (262,148 max on wire). The decoder must not depend on named-pipe message boundaries. RFC 7464 JSON Text Sequences is the strongest competitor because RS delimiting resynchronizes after malformed/truncated elements; the length choice instead treats a torn frame as connection failure + cursor reconnect (simpler, obvious allocation bounds). This is a framing recommendation, not a serialization-library selection (gRPC/MessagePack/Cap'n Proto deferred).
- **Protocol version (source-documented negative finding).** Every `m1b-broker/1` message fixes `protocol_version` exactly; `HELLO`/`WELCOME` carry no major/minor range or schema epoch and there is no in-band pre-admission `REFUSAL`. The only honest v1 rule is exact-match rejection of any other version: no v1 downgrade, no schema-epoch negotiation.
- **Capabilities.** `WELCOME.capabilities` should be the intersection of client request, broker support, and current authenticated operator/GoalSpec authority; returning a capability never creates authority. A client requiring an absent capability must decline the session.
- **Cursors (inferred).** Prefer **event-sequence** cursors for the durable broker event stream; count raw decoded payload bytes separately for credit. `utf8-byte` is only for streams whose durable identity is explicitly a byte offset.
- **Flow control.** Per-view additive byte/event credit, monotonic contiguous ACK, bounded per-view pending state, no canonical-writer wait on any view, and mandatory `RESET` on a real replay gap. Proposed normative reading of the M1B prose conflict: a **strictly forward contiguous ACK releases new pending state; duplicate ACK is a no-op; backward ACK is refused**. Credit exhaustion currently remains reset-requiring unless consciously changed.
- **Gap/replay recovery.** `HELLO → WELCOME → (gap) RESET → SNAPSHOT → ACK → fresh CREDIT → EVENT`; a non-RESET continuation after a detected gap (`requested_cursor < replay_floor`) is a permanent refusal for that stream incarnation.
- **Snapshot blocker (source-documented negative finding).** `SNAPSHOT` carries only `snapshot_digest`, no bytes or materialization reference. A digest identifies/authenticates material but does not materialize it, so v1 replay repair is not self-contained unless another ratified contract retrieves the bytes.
- **Cursor rollover blocker (arithmetic).** M1B cursor/count max is 2,147,483,647; at 1,000 events/s that is ~24.9 days (100/s ~248.6 days). Long-lived detachable sessions need a stream-incarnation rollover rule before v1 can be called durable. A fresh `stream_id` is the natural candidate but the transition is unspecified.
- **Reconnect/idempotency.** A durable command ledger keyed by command identity and bound to daemon epoch, process epoch, stream and lease: new ID → record intent → attempt delivery → record delivered/refused/`uncertain`; identical duplicate → replay existing disposition, never redeliver; same ID + different command → conflict; stale epoch/lease → stale refusal. Ambiguous crash outcomes are `uncertain`, never blind replay. `RESIZE` follows the same rule. View EOF / half-close / abrupt disconnect / daemon restart / PTY output EOF are all **not** process death; exit requires an OS observation tied to the recorded process epoch/stable identity.
- **Process containment (primitives documented; completeness unmeasured).** Creation-time containment is the theme. Windows: Job Object membership via `PROC_THREAD_ATTRIBUTE_JOB_LIST`, breakaway disabled, kill-on-close, membership verified before normal execution; ConPTY is terminal I/O, never containment. The repository's **locally observed** bounded probe showed a create-suspended-then-associate gap let a child survive outside the operation Job, while creation-time Job listing closed the tested gap. Linux: dedicated cgroup v2 boundary, child at birth via `CLONE_INTO_CGROUP` where admitted, pidfd for stable identity; session/process-group state is PTY job-control machinery, not containment. Full descendant-tree termination on the complete supported matrix remains **unmeasured/unknown**.
- **Watchdog and Stop.** A watchdog works from recorded ownership plus independent observation, states spanning `starting`/`contained-running`/`exited-awaiting-reap`/`orphaned`/`escaped`/`hung`/`zombie`/`terminating`/`partial`/`unknown`/`terminated`; no automatic relaunch from ambiguous state. Aggressive/Full/Lazy Stop must not collapse; report separate stages (offered → accepted → recipient fence → cancellation/termination delivered → owned settlement → external settlement), each yes/no/unknown. A transport ACK proves at most a protocol observation.
- **MCP/stdio and tool broker (freshness flag).** Current MCP 2026-07-28 generation differs materially from the older initialize/session model; the repository's old pinned-SDK notification-eviction observation is **historical/local evidence for that pinned version, not a current-v2 fact**. Keep MCP/stdio behind a bounded adapter (finite parser buffers, declared max record, dedicated stderr draining, no handler that blocks the sole reader); no correctness-critical fact may rest on an unrecoverable lossy notification. The tool broker is separate from the terminal channel: per-call grant recheck, command ID, deadline/budget, output caps, containment identity, and receipts; advertised tool availability is not authority; tool output is untrusted evidence. ANSI/VT/OSC/DCS and protocol-looking strings are always terminal payload data and never enter the IPC decoder.
- **Topology (inferred from repository requirements).** Views (terminal/observer/control) attach to the `recursion` daemon as authenticated local IPC clients carrying cursor + credit; the daemon owns canonical state and admits commands to the process broker; the broker owns PTY/ConPTY I/O and managed processes; the tool broker and bounded MCP/stdio adapter sit behind a separate boundary. Presentation clients remain projections; PTY bytes and tool results are data, never authority.
- **Membership vs completeness (evidence distinction).** The report stresses that documenting a child placed in a Job/cgroup does **not** prove every causally resulting process stays there; a subprocess may use an allowed breakaway, migrate with sufficient authority, invoke a privileged helper, or cause an external service to create work under another owner. Chaos tests must target named escape paths ("spawn child; kill parent" is not sufficient).
- **Durable ordering.** Durable/canonical append must occur before projection delivery, and a reserved control reserve must keep view bulk delivery from starving Stop/revocation/control traffic.
- **Wire-before-renderer.** The protocol-layer conclusions (framing, cursors, credit, reset, leases, command dedupe) are specified without choosing a renderer; the renderer remains deliberately unselected.

## Recommendation and falsifier

The report's disposition is **conditional adoption, not completion**: adopt the ownership model, preferred local transports, deterministic bounded framing, event/credit/replay semantics, creation-time containment strategy, and separate MCP/tool-broker boundary as the leading DS-23 design; keep the renderer/library choice open; and **do not declare the protocol frozen** until the freeze blockers are resolved. Freeze blockers: (1) exact-version-only vs a new broker major with version/schema/refusal negotiation; (2) snapshot materialization independent of storage; (3) cursor rollover/incarnation; (4) normative ACK-release wording; plus the native Windows/Linux chaos matrix.

Each recommendation names a competing option and decisive falsifier (e.g. loopback TCP + bearer token falsifies named pipes if it passes equivalent local/identity/fuzz tests with lower complexity; creation-time Job membership fails if it breaks a launch-critical supported route while an alternative closes the same gap; length framing fails if torn/corrupt-stream tests show a required recovery target that only RFC 7464 resynchronization meets; event cursors fail if byte offset proves the more stable replay identity). The report supplies a large preregistered cross-platform fault matrix (auth, framing, gap/reset, slow-view, duplicate-input, containment birth/breakaway/migration, broker death, MCP flood/deadlock, VT injection, daemon restart) with per-case stop conditions and required pins.

## What this does not prove

- Full descendant-tree termination on the complete supported Windows/Linux matrix remains **unknown**; no source or probe establishes it.
- Slow-client isolation and flow-control correctness are **unproven from schema alone**; they need an implementation plus soak/fault evidence across transport → frame accumulator → decode → canonical writer → per-view projection → render sink.
- The length+JCS framing choice is not measured operationally; RFC 7464 in-stream recovery is a genuine unresolved competitor.
- Current MCP v2 notification/backpressure behavior is **unknown** and must be pinned and fault-tested; the old pinned-SDK observation does not transfer.
- No renderer, multiplexer, GUI toolkit, IPC library, serialization library, cursor store, snapshot format or retention engine is selected.
- No byte-exact cross-implementation interoperability, no numeric queue/deadline bounds, and no Lazy Stop timeout/escalation policy are established.
- Nested/alternate Job behavior, Linux cgroup migration by privileged helpers, and external-service-created work remain named escape paths, not settled cases.
- The Windows `WIN-HANDLE-LEAK` / broker-death and Linux `LNX-MIGRATE` / `LNX-BROKER-DEATH` outcomes are test designs; no result is reported here.
- The claim that `protocol_version`-only exact matching is safe is unfalsified by any interoperability fixture; the report labels the missing negotiation a source-documented negative finding, not a measured failure.
- No control-plane or protected-path change is proposed; the report treats the higher-precedence `CONTROL_PLANE.md` reading (no runtime effects, no v1/v2 control-plane changes) as operative.

## Open Owner decisions

- Is `m1b-broker/1` immutable for DS-23 (accept exact-version-only), or may DS-23 propose a new broker major with version intervals, schema epoch/digest, capability sets and typed pre-admission refusal?
- What already-ratified contract turns `SNAPSHOT.snapshot_digest` into verifiable view bytes at the exact cursor (storage-neutral)?
- How should cursor rollover/incarnation behave before 2^31−1, and how does a client distinguish rollover from stale/replayed state?
- Is "same OS user/logon identity" sufficient to attach, or must Recursion distinguish the approved executable from any same-user process via an installation key/attestation?
- Which Windows client matrix (desktop, lower-integrity, AppContainer, elevated), and which Linux kernel/cgroup-floor profile, are admitted; and what happens on a host lacking the required containment profile?
- Is the "credit exhaustion is reset-requiring" behavior retained or changed?
- What is the Lazy Stop timeout/escalation policy when a boundary never arrives?
- What MCP/stdio numerical bounds (partial-line/message buffers, tool output caps) apply, and what is the exact command-receipt event payload schema?

## Relevance to later waves

This report fixes the semantic spine later waves should consume as constraints: OS-authenticated local transport, deterministic bounded framing with exact-match v1 versioning, event cursors plus independent byte/event credit, mandatory RESET on gap, durable command-id idempotency across epochs/leases, creation-time containment separate from PTY/session semantics, and a separate tool/MCP boundary. Later protocol or terminal-view work must not reopen the detachable-terminal ruling or move a view/adapter into authority. Before any freeze, the four blockers and the preregistered native chaos matrix must pass; any wave that would select a renderer, IPC or serialization library, or claim full tree termination, is making an Owner decision this report deliberately left open.
