## Conclusion

Make every semantic obligation discoverable independently of record schemas, with explicit maintenance ownership and coverage across all commands that can change its operands. Admission already belongs to the deterministic kernel; these findings do not establish a missing governance authority. Start by comparing inspectable per-command validators against a versioned declarative invariant catalog with bounded generated checks. Both can preserve the four-function core and sole authority/writer. Neither automatically establishes correctness.

The recurring gap is an **unchecked semantic join within the existing kernel authority**. Record validity establishes that a reference has the right shape, a number is unsigned, or a verifier has a role. Admission must additionally establish that the exact referenced exception exists, the replacement epoch advances correctly, or this verifier owns this gate. Derived records and post-transition state need their own relational obligations. Fresh envelope authority cannot repair a stale payload binding; later output verification cannot settle an earlier ambiguous effect.

[SG coverage](../semantic-guard-research/SEMANTIC-GUARD-COVERAGE.md) documents useful existing guards alongside these gaps. Its [matrix](../semantic-guard-research/coverage-matrix.json), especially C04–C06, C12, C14–C19 and C22–C24, prevents “missing everywhere” overclaims. [SK](../additional-kernel-research/SUPPLEMENTAL-KERNEL-AUDIT.md) contributes two admission candidates and three model-adequacy/premise findings. The latter are not additional implementation defects.

## Two conforming designs

**A — Explicit command validators.** Each command has an inspectable semantic routine with a declared read set, exact reference-resolution rules, applicable obligations, proposed writes and postconditions. Small shared pure helpers implement exact lookup, arithmetic and binding comparison. A separate obligation-to-command register exposes omissions, including commands that overwrite previously quarantined state. This permits domain-specific diagnostics and unusual contracts without creating a second programming system. Its risk is drift: a new completion path can forget an existing ambiguity guard.

**B — Versioned declarative catalog.** Each obligation declares typed operands, bounded joins, applicability, predicate, transition phase and deterministic refusal classification. A pinned interpreter or generator produces checks and their command dependency map. Only a deliberately finite expression surface is admitted: exact lookup, bounded quantification, set attenuation and typed arithmetic. New predicate forms require core review; unrestricted callbacks would erase the inspection and cost advantage. Its risk is correlated mistakes in the catalog, dependency compiler and generated implementation. A perfectly generated wrong join remains wrong.

Both retain `decode`, `admit`, `reduce`, `derive_work_packet` as the semantic interface described in the [architecture](../synthesis/MODEL-ARCHITECTURE.md). Validators are internal composition, not another authority service. All facts, logical times and state cuts are explicit inputs. The runtime protects the admitted cut through commit; neither design polls mutable stores or delegates current-policy resolution to a plugin.

**Recommendation and comparison:** use A as the first review baseline and B as a genuine challenger, retaining the same obligation register, semantics and independent corpus. Compare accepted change effort, review defects, diagnosability and bounded work across feature additions; count catalog/compiler maintenance as B's cost and duplicated guard maintenance as A's. A loses if equivalent B materially reduces independently reviewed maintenance without hidden semantics or weakened coverage. B loses if a required contract needs opaque escape hatches or its dependency map omits an affected command. Passing establishes neither completeness of the specification nor a universal efficiency win. A shared register with handwritten checks is already A, not evidence that generation helped.

## Ownership and evolution decisions

**Keep dependency coverage explicit.** The semantic owner reviews every command that writes an obligation's operands, including derivation and terminal-state overwrite. Rival: recheck all applicable invariants over the entire bounded aggregate after each proposal, avoiding an incremental dependency map. The decisive discriminator is the existing SG08 completion path: either approach must preserve the ambiguity constraint despite a gate pass. A missed writer falsifies incremental coverage; unacceptable full-scan work falsifies its rival under the adopted bound. Neither proves that the aggregate contains every relevant external fact.

**Freeze semantics with artifacts.** Pin the command/profile version, obligation register, implementation or catalog/generator, refusal order and evidence corpus. Separate specification owner, implementation owner and independent acceptance reviewer; generation cannot collapse these responsibilities. Rival evolution strategies are retaining version-specific interpreters or using reviewed bounded migrations with exact old-to-new semantic mappings. Historical receipts stay historical under either. A newly strengthened rule may flag old decisions as nonconforming without rewriting their bytes or silently giving old work fresh authority. A migration that changes a historical result without a declared mapping, or an old interpreter accidentally used for new admission, is decisive failure. Compatibility passes do not establish historical decision soundness. Frozen M1A expectations, including SG03's mismatched packet, require a separately reviewed correction/version path, not silent replacement.

**Keep plugin contributions subordinate.** Plugins may propose typed operation descriptions and evidence; they cannot install executable admission hooks, supply authoritative current refs, weaken mandatory core obligations or acquire a writer. Disabled discovery remains bounded host-owned metadata inspection. Rival: a reviewed bounded declarative extension compiled into a newly pinned core profile. The discriminator is whether disabling/untrusted metadata changes admission semantics or triggers execution, or whether an extension bypasses an existing obligation. Either failure rejects the boundary. Passing does not qualify plugin containment, rights or credential separation under D029.

**Bound validation and explain refusal.** Pin limits on referenced records, graph size, join fan-out and predicate evaluation; reject oversized/unsupported work explicitly rather than skipping checks. A offers auditable manual bounds; B offers structurally checked bounds, with compiler correctness still a dependency. Compare complete validated inputs at equal limits. Unbounded lookup, implicit I/O, or “success” after evaluation exhaustion falsifies either arm. Diagnostics identify obligation/version, operand fields and source cut using authorized disclosures, with stable primary-error precedence. A rival returns only a stable public refusal plus access-controlled detail. Compare independent diagnosis accuracy and leakage, not verbosity. Neither deterministic operation counts nor good errors prove wall-clock latency, availability or secret noninterference.
