Research synthesis dated 2 October 2026 UTC. Repository authority pin: `73d70505b8c266fbb08d820d304ebd2e68ac7f1b`. This is a proposed architecture and evidence handoff, not an Owner decision, implementation, route qualification or permission to execute. All new behavioral tests are UNEXECUTED. Final input status and byte pins are in [integration status](INTEGRATION-STATUS.md) and [input register](input-register.json).

## Decision to prepare

Develop a **Recursion-owned authority and continuity core with two independently useful execution paths**: a small native model/tool loop and adapters to upstream-owned loops. Both consume the same current task, authority, artifact, reservation and effect contracts. Neither upstream sessions nor Recursion context summaries are the source of accepted intent. A session can be replaced without minting permission, replenishing a budget or forgetting an ambiguous effect.

Use receiver-recorded services as the first complete comparison baseline. Keep a bounded resident hub and subordinate workflow assistance as serious alternatives. Compare them at equal required capabilities and equal durability before changing activation or residency. The immediate decision is what evidence to build, not a language, store, framework, model, renderer, transport or vendor selection.

The integration reveals three especially important boundaries. First, read authorization is not always a canonical mutation: a bounded same-cut status query can remain read-only. Second, every transformation changes evidence obligations without acquiring authority: OCR, memory, a source snapshot, a room reply and a plugin import all need exact lineage and declared loss. Third, the irreversible receiver boundary is where stale authority must fail; a local admission record, Stop request or launch receipt alone cannot supply that property.

The detailed [ownership and field map](OWNERSHIP-AND-FIELD-MAP.md) reconciles actual candidate schemas. The [prioritized test handoff](INTEGRATION-TEST-HANDOFF.md) joins the lanes around failure traces rather than assembling independent happy-path demonstrations. Public source facts remain in their canonical homes, indexed by [shared evidence navigation](../shared-evidence/source-facts.md); this synthesis adds original architectural analysis without duplicating those source summaries.

## One state model with several owners of evidence

The core owns accepted GoalSpec and PlanRevision references, current grants, work and writer fencing, scoped Stop, command dispositions, cumulative allocations, operation identities and accepted transitions. A separately identified receipt journal can retain denied or duplicate delivery observations without inventing a second state authority. Large payloads, private source bytes and media live behind governed artifact references. Immutable events should avoid embedding payloads that later need erasure.

A task is best represented as a product of independent state dimensions, not one optimistic status enum:

- Intent and authority: current accepted goal/plan, authority revision, eligible effect classes and bounded approvals
- Execution: selected native/upstream route, route epoch, attempt, process/node incarnations and admitted work lease
- Content: source/workspace binding, context epoch, exact input manifest, provenance and loss
- Effects: each logical operation's dispatch evidence, receiver state, uncertainty and settlement
- Resources: settled consumption, outstanding reservations and uncertainty annotations in their own units
- Verification: candidate identity, gate identity, review state and independently accepted outcome
- Presentation: view/subscription identities, source cuts and installed projection generations

Three commonly conflated revision pairs need typed mappings. T's `route_descriptor_epoch` names the exact capability descriptor revision, not the route assignment `route_epoch`. Y's `configuration_epoch` names a target effective/application generation, distinct from configuration content `configuration_revision` and `effective_config_ref`. Release artifact identity/revision is separate from each target's release activation epoch. A fresh unrelated generation cannot repair revoked work permission. These are proposed production mappings, not renamed frozen fields.

There is no total order forcing every effect through every observation state. A receiver observation can arrive before a local delivery acknowledgment; independent verification can concern output bytes while payment settlement remains pending. Store these as attributable facts with causal links. Do not overwrite an earlier uncertainty merely because a later unrelated stage succeeded. The vocabulary received, delivered, admitted, started, observed, settled and verified always names its subject and observer.

The kernel's four semantic functions remain `decode`, `admit`, `reduce` and `derive_work_packet`. They receive explicit bounded facts; they do not read clocks, make model calls, launch processes or poll stores. The runtime validates and supplies observations, protects the current state sequence during admission/commit, commits the event and durable dispatch intent together where required, and only then allows dispatch. The receiver independently gates the effect against current applicable fences. A successful local transaction cannot atomically cover an unrelated external service without an evidenced participating protocol.

### Read and mutation paths

A read path authenticates the reader, resolves current disclosure scope, selects an explicit source cut and interprets retained state through a bounded pure query. It need not write a new canonical event merely to render status or inspect already-retained history. Cached authorization must obey its revocation contract; yesterday's readable artifact is not automatically readable today. Query cost and optional audit retention can be accounted without turning the renderer into a work scheduler.

A new source observation, registered derivative, configuration change, accepted room message or work proposal uses its proper admission path. Hydration inside a previously admitted read envelope may remain a scoped read; a new recipient, remote request, write, paid transform, retained copy or effect uses the corresponding disclosure/effect obligations. Merely calling an API read-only or using a GET verb establishes none of these conditions.

Frozen M1A observation commands remain PAUSE-sensitive. Retained-history inspection is distinct from admitting a fresh observation while paused. M1C's pure trace classification establishes only its stated classifier properties. The broader production query envelope proposed here neither changes M1A/M1B bytes nor upgrades M1C into a production query implementation. M1B's closed wire union, cursor, CREDIT, ACK and RESET meanings remain frozen; application-level manifests and controls are separate versioned contracts.

## Competing complete architectures

| Candidate | Placement and state ownership | Strongest case | Decisive risk and comparison |
|---|---|---|---|
| A Receiver-recorded services | Core intent/receipts plus bounded operation coordinators and independently recorded receiver facts; services activate as needed, with optional warm resources | Small inspectable native loop, explicit crash cuts and limited idle work | More bespoke lifecycle composition; compare recovery correctness and engineering effort against C at equal residency |
| B Bounded resident hub | Same core and receivers; enabled session, stream and interaction coordination stays resident within adopted bounds | Repeated interaction and many concurrent views may benefit from stable pumps and warm sessions | Idle cost, stale ownership and restart concentration; compare against A with identical affinity, workload and durability |
| C Subordinate workflow assistance | Same core, A or B's residency, plus a helper journal for due work and continuation delivery | Many long waits and delayed operations may justify less custom scheduling/recovery code | Duplicate retry/authority histories, hidden children and migration complexity; helper replay must propose work for fresh admission |

All three include the accepted opt-in rooms, memory, multimodal, scheduling, adaptation, GUI and remote capabilities. Demand activation, residency, durability, process placement, packaging and formal proof boundary are independent axes. A durable demand service is possible; a resident process can still lose its state. A workflow library cannot be credited with availability while its extra journal, deployment, upgrade and recovery work are omitted.

Choose A as the initial falsification baseline because its operation boundaries expose the hardest unresolved contracts with less simultaneous machinery. This is a research priority, not acceptance of its superiority. If B satisfies the same floors and wins the adopted interactive objective after idle and recovery costs, B should win that profile. If C reduces independently accepted recovery/maintenance burden without duplicate owners or worse resource bounds, C should win that profile. A null benefit retains the simpler conforming default while the comprehensive opt-in capability remains available.

### Formal boundary competition

The split arm keeps the four-function deterministic kernel and a bounded broker refinement. The inclusive arm includes broker lifecycle and receiver-related abstraction directly in the formal transition system. Both must expose the same command identity, current writer/work/pause epochs, reservation conservation, dispatch ambiguity, receiver fence installation, process ownership, event/receipt cuts and observably permitted control behavior. Hold command/event bounds, fault placements and fairness assumptions constant before comparing exploration or proof cost.

The split's abstraction map must explain every externally visible transition, including refusals, duplicate receipt delivery, cancellation races, late observations and recovery. Internal broker steps can stutter only if they do not conceal observable authority, budget or lifecycle change. Prove invariant preservation and any claimed progress under named scheduler/storage assumptions; safety success alone is not liveness. The inclusive challenger wins a boundary decision if it exposes a reachable race that the split mapping cannot represent without strengthening the aggregate. Moving necessary broker state into the aggregate preserves the four-function interface and repairs the abstraction; it is not a failure of minimality.

The FU03 audit is the first leverage point. Historical four-ID diagnostics are useful bounded evidence, not a full refinement proof. Its [seven-step candidate witness](../gaps/fu03-candidate-witness.json) is an unexecuted inference under enlarged bounds: GrantLease, Start, PrepareEffect, MarkDispatch, SubmitFail, ArmTimer, FireTimer leaves an InFlight effect with retry readiness. Determine independently whether timer readiness merely permits a later guarded check or itself violates the intended semantic invariant. Do not weaken the invariant, treat the witness as a rerun, or infer coverage of the full model from its diagnosis.

## Native loop and upstream loops

The native path owns its control flow. A provider transport produces bounded model-response observations; the Recursion loop assembles context, records the response, parses proposals, requests tool admission, observes results and decides the next eligible iteration. A model library may supply a narrow codec/transport capability; an embedded upstream SDK that owns planning, tools, retries and compaction is an upstream loop with an adapter, not the native loop.

A native attempt follows this proposed sequence: admitted work packet → bound context compilation → model-call reservation/admission → bounded streamed observation → response closed or partial → typed proposals registered → individually admitted tool operations → reconciled observations → next eligible iteration or gate submission. Waiting for a person, dependency, capacity, Stop boundary or unresolved effect is an explicit state. A partial response is retained as partial; a truncated tool proposal never becomes a complete executable request. A streamed display fragment cannot skip the proposal/admission boundary.

For a tool batch, record source order, declared independence, per-operation identity, actual dispatch/completion order and join policy. Parallel execution is eligible only if its shared-resource and effect contracts permit it. One failed or cancelled tool does not erase siblings. The next model call receives an explicit admitted result set and unknowns. Compare sequential dispatch against bounded parallel batches on identical tasks; a shared-state dependency or duplicated effect rejects a purportedly independent batch regardless of speed.

An upstream adapter owns translation, process/session correlation and the exact route capability/loss record. It does not own the accepted goal, budget or effect truth. The route binds build, transport, method set, configuration, account class, allowed control semantics and observed conformance. A native session/fork/subagent ID remains an alias to a canonical object under the exact route epoch. It is not an actor identity, grant or new budget.

Before assigning any workflow, close every reasoning role: task solver, planner, reviewer, compactor, memory extractor, media helper, recovery assistant and learned router if enabled. In upstream-only mode each enabled role must be deterministic or explicitly served by an eligible upstream route. No invisible native fallback is allowed. A deterministic unavailable/refused result is preferable to hiding an extra model call. Status, attach, explain and replay remain model-free under their declared contracts.

Upstream-native fan-out must fit an admitted, observable and enforceably bounded subtree. If child creation cannot be intercepted, its entire permitted subtree needs a valid pre-reservation and controls at the qualified boundary. If that cannot be established, the profile cannot claim effectful bounded fan-out; an independently admitted proposal-only use is a different candidate. Parent-inclusive meters and child meters require explicit inclusion algebra. Hidden child use remains unknown, not zero or a second sum.

Each logical effect has one retry owner across SDK, adapter, scheduler and workflow helper. New wire IDs, a reopened connection or a fresh upstream session do not create a new logical effect. Protocol continuation, cancellation and task expiry map to observations, preserving the [canonical protocol edge contracts](../protocol-edges/report.md). Capability translation can be lossy only when the requested policy expressly permits that loss; unsupported steer cannot silently become queue.

## Trusted launch and confined execution

The launch architecture separates the canonical authority service, runtime supervisor, operator-provisioned launcher, pinned credential-facing upstream component, untrusted tool/plugin domains and read-only verifier. Provider credentials remain outside Recursion's readable/control domain for the delegated path. A launcher reference is classified by actual authority: if possession enables invocation, it is sensitive bearer-like authority requiring protection and attenuation. Opacity alone establishes no non-access property.

Strong D029 qualification requires documented separation support in the exact unmodified upstream build between credential-facing execution and untrusted tools/output paths, or specifically evidenced equivalent enforceable support. A wrapper, changed parent process or launch broker cannot manufacture that separation. Direct memory/filesystem denial and induced flows through prompts, helpers, configuration, plugins, diagnostics and output must all fit the declared threat model. The credential-bearing component is a trust dependency; a malicious secret-bearing component with unrestricted output defeats a generic non-export claim.

Failed strong preflight closes execution admission. Strong-required tasks are refused. A policy-only label does not authorize continuation; eligible weaker-mode execution needs separate operator admission of the exact profile and limits. There is no automatic downgrade or route switch. The [trusted-launch report](../re/report.md), [isolation contracts](../ru/candidate-contracts.json) and [operating-mode counsel questions](../rh/report.md) retain independent technical, entitlement and legal seams.

Execution grants are a typed intersection of parent authority, manifest request, current policy, scope, lifecycle fences, resource reservation and demonstrated enforcement ability. A publisher signature, cached artifact, first-party label or prior acceptance changes evidence, not this intersection. Filesystem, network, executable, environment, IPC, device, clock, entropy and service permissions remain separate dimensions. An unsupported mandatory bound refuses the profile instead of falling back to broader host access.

Full owned-tree termination needs creation-time identity and independently observed descendants, service relaunchers and remote obligations. Resource containment, authority mediation, confidentiality, software provenance, rights and code identity are separate claims. A source signature is not containment; a killed process is not external rollback. All current exact-platform strong profiles remain unqualified in this research.

## Context media memory and workspace continuity

Use one internal ArtifactRef with all four Q fields: `object_type`, `id`, `version`, `content_digest`. Its digest is a byte-integrity identity inside the declared privacy domain. Across a boundary use a newly authorized audience/purpose-scoped opaque handle, resolved under current policy. The handle must not itself authorize access. If an implementation makes possession sufficient, classify it as a sensitive capability and reject its use as the proposed non-authorizing public reference.

The shared ContentEnvelope uses Q's exact eighteen required names, including `project_and_audience` and `privacy_domain_id`. Q's MemoryProjection `project_id` is a different field. P's provenance dimensions normalize through explicit checked mappings; T's media/selector/loss fields and Y's workspace facets are extensions. X transports references and scoped bindings; it does not create another content owner. The full reconciliation is in the companion map, with T's [214-row field map](../rt/field-map.json) as the detailed candidate source. Agreement on names is compatibility evidence only.

The initial X TransferBinding ordering exposed a cross-lane defect: it placed publication before copy/evidence/accounting registration. The integrated candidate corrects the lifecycle at **both** remote disclosure and task publication. Local private staging may occur first. Before releasing remote manifest metadata or any chunk, durably register a disclosure intent, expected potential-copy inventory linkage, complete known lineage and applicable reservation under the canonical owner; then check current rights/fences at the protected release boundary. Receiver quarantine does not undo disclosure to that node. Before task publication, verify and register the actual received representation and its copy/lineage, recheck current rights, then publish. Append actual observations and settle afterward. Intent is not proof of transmission: a crash can leave possibly disclosed content unknown. This proposes a separate intent record/linkage; it does not invent planned/staged values in Q's existing CopyRecord status enum. The exact source-lane repair and independent runtime evidence remain separate.

Every derivative retains immediate parents and the complete possibly influential input set. For model transforms the conservative set is the whole visible context, not just returned citations. Reader and purpose permissions intersect; source influences and incomparable restrictions accumulate. Retention deadlines do not reset through summarization, embedding or re-observation. Declared media type is separate from validated type. Source capture time, retrieval time, ingestion time and canonical record time remain separate observations.

Context compilation has four layers: exact accepted control references; required current source, workspace and operation evidence; optional task-relevant memory and retrieval; renderer/provider serialization. It binds the exact input set, recipient, route profile, current rights, configuration, source cut and declared loss. Required instructions, pending approvals, gate definitions, unsettled effects and cumulative reservations stay outside lossy summaries. A reference whose bytes or rights cannot be resolved blocks the claim requiring it, even if a summary sounds complete.

One compaction governor owns policy per route epoch. A route using upstream compaction records its capability/loss; a Recursion-owned compactor is separately admitted and counted. Switching governors is a new explicit context boundary. A fresh context cannot preserve hidden provider state by assertion. Cold reconstruction from the minimum exact capsule is the control against which summaries, retrieval and warm caches must justify quality and total-work benefit.

Media processing is a sequence of distinct governed representations: original, decoded content, OCR/ASR, selected frames, caption, translation, summary, preview and generated output. Each transform has a producer operation, input/output refs and loss declaration. A caption is not the original image; extracted text is not all document structure. Approving a thumbnail cannot authorize raw upload. Compile final recipient-bound content or bounded stream segments before egress; unknown final stream bytes cannot receive an invented final digest. Exact-all-bytes approval requires buffering or refusal when streaming cannot meet it.

Memory is a disposable projection of admitted evidence. Typed facts, preferences, decision summaries and lessons may aid retrieval; only separately resolved canonical decisions are operative. Suppression, expiry, redaction and hard deletion have different outcomes. Copy inventory includes indexes, embeddings, prompts, summaries, logs, exports, backups, disconnected spools and known provider/recipient copies. Revocation blocks future controlled use; it does not erase earlier disclosure or human knowledge. A deletion request with unknown external copies remains partial or bounded to a controlled subset.

Workspace identity is neither a path nor a commit. One task binding revision names one registered workspace manifest and an exact vector of repository, snapshot, candidate and materialization identities. A clone creates a physical instance; association with an existing logical repository or a new logical fork requires admitted intent. Changing a locator cannot create authority. Graph edges distinguish canonical domain facts, validated source observations and derived interpretations; VCS ancestry and canonical event order are separate relations.

A source snapshot declares byte/logical/coherence coverage. Immutable closure with a coherent dirty overlay, a qualified storage snapshot, and enforceable all-writer quiescence are viable coherent candidates. Repeated scans with equal before/after hashes can miss ABA and mixed-time state; that observation profile must refuse coherent-fork claims. Materialization verifies actual destination bytes/types/metadata and isolation from original aliases. It does not issue an execution lease. Application is a separately admitted effect against an exact base and protected write window; uncertain partial application never triggers blind clean, stash, reset, fetch, rebase or overwrite.

Conversation fork, source capture, logical source fork, worktree allocation, branch creation and candidate application are six different operations. Forks can reference historical evidence and accounting, but never clone live approvals, grants, leases, reservations or writer authority. Any reservation split is its own conserving canonical operation. The [workspace contract](../ry/candidate-contracts.json) and [node transfer contract](../rx/candidate-contracts.json) meet at immutable bindings and verified materialization receipts, not shared mutable paths.

## Rooms bounded autonomy and adaptation

Rooms own addressable communication and visibility, not a competing plan. An addressed message binds sender, recipient, exact actor/attempt/turn where required, content ref, purpose, route epoch and delivery policy. Sender acceptance, receiver ingress, model-visible consumption and semantic adoption remain distinct. A stale steer is not delivered to a successor by convenience. Receiving a message never turns its prose into an Owner instruction.

A CoordinationLease covers one room, one workflow step, a bounded participant set, permitted proposal verbs, context audience, reservation slice, depth/outstanding limits and expiry/revocation. It cannot amend GoalSpec, widen membership, self-renew or settle cross-goal conflicts. An ARM executive's tactical plan permission is independent of its step-coordination permission. The sole canonical writer commits at most one valid transition for an expected step revision after checking both where required. Returning coordination to Head after expiry does not authorize inference while Stop remains active.

A CampaignBinding bounds unattended work by accepted goal/configuration, admissible event sources, expiry, cumulative resources, review obligations and notification policy. A ScheduleSpec creates eligibility, never authority. The wake key `(schedule_id, schedule_revision, nominal_occurrence_id)` deduplicates an occurrence before executor eligibility. A wake resolves current goal, plan, source, rights, route, plugin, grants, Stop and reservations afresh. Civil-time interpretation, clock uncertainty, missed-run policy, overlap and catch-up bounds are explicit. Waiting must not occupy the sole executor needed to satisfy the wait.

Autonomy is useful only if it produces independently verified progress toward the accepted goal. Activity, tokens and a model's self-report are not that progress. A timer, dependency completion, human reply or quota reset can invite reevaluation but cannot expand scope, settle a result or renew money. Human-required actions hold at their exact seam. Resident, demand and workflow-assisted schedulers compare under the same canonical wake contract; an owner-invoked bounded batch is the control, not a substitute for required scheduling capability.

Adaptation consumes an append-only join of eligible candidates, actual assignment, outcomes and accounted costs. It may propose choices inside already permitted policy surfaces; hard authority/privacy/effect/quality floors are never reward terms. Policy publication is a separate independently reviewed and explicitly authorized transaction, with exact artifact/scope, expiry and rollback conditions. Read-only shadow scoring cannot establish counterfactual quality for actions never taken. Missing propensities, unsupported actions, delayed outcomes and unidentified quota debit limit what can be inferred.

Stop fences late policy promotion. A preauthorized rollback installs a new monotonic revision and revalidates the previous artifact under current grants and floors; it does not restore old authority or undo spend. No adopted margins, measurement, corpus or independent runtime evidence exists here. Synthetic classifier numbers in lane appendices remain test constants, never proposed production thresholds. The fixed-policy baseline remains necessary even when adaptation is built and opt-in.

## Resource and control conservation

For each separately typed cumulative pool, declare whether the limit is gross or already net of withheld headroom and how the reserve is represented. With disjoint withheld headroom, the gross-cap form is `settled consumption + outstanding reserved upper bound + withheld headroom + proposed new reservation <= gross approved limit`. The equivalent ordinary-work net-cap form subtracts that headroom exactly once from the limit. A tagged reserve already inside outstanding reservations adds no separate headroom term. Recovery admission atomically transfers its allowance from withheld headroom into an outstanding reservation; it does not mint capacity. Settled consumption and outstanding reservations are disjoint. Uncertain liabilities are a subset or annotation of the outstanding reservations, never an extra addend. Settlement transfers the corresponding reserved liability to measured consumption atomically and releases only demonstrably unused remainder. A missing trustworthy finite upper bound refuses new strict-cap admission against the affected pool.

Instantaneous host capacity has a separate typed predicate over current occupancy, admitted live allocations, protected capacity and the proposed peak demand. Cumulative settled consumption is not current RAM occupancy. Preserve pool/window/unit semantics instead of applying one arithmetic equation to money, a concurrency slot, memory and a deadline.

Protected writer, Stop, evidence, observer and recovery headroom must be either disjoint reserves or tagged once inside a declared shared-reserve algebra. Do not subtract it from capacity and add it again as unexplained demand. Unlike dimensions such as memory, tokens and review minutes cannot be numerically minimized until converted into justified slot credits. Review queue capacity is an independent limit; unused CPU cannot create a reviewer.

Counters retain unit, source, cumulative/delta mode, interval, inclusion set, reset evidence, attribution and unknown reason. Tokens, money, subscription debit, local resources and human time are separate quantities. Fork, retry, new session, host move, route switch, workflow continuation and calendar rollover do not reset the cumulative campaign ledger. An authorized periodic renewal has its own exact rule. Unknown is not a measured zero, and parent-inclusive child totals cannot be added twice.

Stop begins with the exact target ownership set, mode and current pause policy. Aggressive closes selected-agent admission and interrupts immediately, reporting descendants separately. Full covers the rooted owned set, including monitors and relaunchers; borrowed consultant work is scoped so unrelated activity survives. Lazy closes new admission and waits only for a named already-admitted observable boundary with finite deadline and authorized escalation. Sleeping schedules have no active boundary to finish and are fenced/reaped. Checkpoint preserves references and uncertainty; interrupt requests control; drain permits only its already-admitted bounded allowlist.

Requested, locally accepted, local fence installed, remote fence observed, interrupt delivered, process exited, containment empty, effects settled and independently verified remain separate facts. An offline receiver is unknown. Canonical revocation before remote fence installation leaves an explicit exposure interval. Prevent conflicting replacement effects until the old receiver boundary is established or the task safely holds. A new lease proves permission for its scope; physical non-overlap additionally needs independently observed quiescence when required.

## Shared backend node fabric and replaceable clients

The audited L/V command-identity mismatch has an explicit candidate resolution, now reflected in the revised lane contracts. L originally scoped deduplication by domain/principal/command ID; V uses a domain command identity with actor/auth_ref bound in immutable bytes. This synthesis proposes canonical key `(admitted_authority_domain, command_id)`, with principal/auth_ref and all effect-relevant intent in the immutable digest, and separate client transport/audit IDs. A client principal subnamespace is valid only through a declared injective mapping into canonical command IDs before kernel or V lookup. Changed principal/auth_ref under an existing canonical ID conflicts; current reader authorization still gates historical receipt disclosure. This is an unratified production integration proposal, not a rewrite of frozen M1A.

The shared operation catalog owns meanings, exact typed targets, schemas, preconditions, control semantics and receipt projections. CLI, TUI and GUI compile the same operation into the same semantic arguments; client identity affects attribution, not authority. Queries use an explicit cut/audience/filter. An offline outbox is saved locally, not canonically accepted. Same-ID retry queries the old receipt; changed bytes under that ID conflict. Expired receipt history does not authorize replay.

Runtime actor/process lifetime is independent of disposable views. A target has at most one current input/resize control holder; passive views can inspect and maintain drafts, but focus/attach/reconnect never transfers that lease. Owner Stop uses its own authority and is not blocked by somebody else's keyboard lease. Projection bytes and installed cursor change atomically; copied, advertised, received, installed and acknowledged positions differ. Canonical facts precede lossy presentation. Slow readers cannot hold the writer or control path; finite storage pressure can still require admission refusal.

Build TUI semantics and accessible plain-text facts first, then read-only GUI projections, then typed controls, then profile qualification. Keep toolkit choice open. Terminal and graphical renderers need safe Unicode/control handling, keyboard/focus/assistive technology semantics and explicit capability-loss displays. An inaccessible rendering that looks correct fails the required interaction gate. N-view cost, idle work and human review errors belong in comparisons, not only frame speed.

Plugin discovery reads bounded host-owned metadata without loading implementation, running hooks, fetching schemas or activating dependencies. Disabled attributable imports/processes/timers/network/model work remain forbidden; bounded shared inventory cost is measured separately. Import translates foreign contribution semantics with explicit unsupported/loss dispositions. Publication, rights, dependency closure, supply-chain freshness and execution qualification have separate gates. UI mods cannot be inserted into a credential-bearing component to bypass D029. Prior-art code may inform a comparison; no port or universal executable plugin ABI is accepted here.

Node membership, authenticated transport, work lease, writer authority and resource reservation are separate. Enrollment binds an approved node identity and incarnation but grants no task, shell, source read or provider entitlement. Placement first filters current hard requirements; a score cannot trade away residency, privacy, boundary or strict-budget constraints. Control manifests precede scoped content hydration. A transfer binds exact recipient incarnation, source/envelope/representation, authorized range, byte ceiling, current policy and copy/receipt obligations. It transports no provider credentials, node private keys, live permits or duplicated reservations.

Receivers install monotonic scoped fences durably, serialized with irreversible acceptance. Authenticating a node's higher number is insufficient without authorized installation provenance. Core-only machine loss can yield honest unavailability. The selected D020 availability mode adds takeover through the seam, with receiver fencing and complete recoverable checkpoint/suffix evidence. Neither mode promises zero RPO/RTO or reconstructs unreplicated bytes. Recovery first restores current control and unsettled identities, then verifies allowed artifacts/materializations, then requests fresh work admission. Restored bytes, restored control, resumed execution and useful verified continuation are four distinct outcomes.
