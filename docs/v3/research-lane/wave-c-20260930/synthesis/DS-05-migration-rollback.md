## The question

Define the exact *contract* (not an implementation) under which one aggregate can move from legacy writers to v3 without creating two writable truths, define deterministic recovery and rollback before external effects, and define forward-only reconciliation once an external effect may have been accepted. The target is fixed as the synthetic local execution-attempt/lease aggregate; storage engine, language, provider, authentication, deployment and the separate numeric recovery-reservation ledger are out of scope.

## Key findings

- **The sufficient cutover boundary is a versioned ownership checkpoint, not "the imported data looks the same."** It must simultaneously prove complete writer enumeration; quiescence of every legacy writer; a monotonically higher writer epoch enforced at both admission and durable execution; exact canonical event-prefix/order parity; projection parity; deterministic crash recovery; a tested backup and reverse-reader path; and exclusive v3 ownership. The report cites etcd's principle that a lease alone does not ensure mutual exclusion after a client goes stale — the protected resource must validate a version/fencing value.
- **The migration progression is retained unchanged:** `UNIMPORTED → SNAPSHOTTED → VALIDATED → LEGACY_WRITERS_QUIESCED → FENCE_ESTABLISHED → IMPORTED → REPLAYED → SHADOW_READ_VERIFIED → V3_OWNER_ACTIVE → CHECKPOINTED`. Each transition has a required precedent and a fail-closed outcome; e.g. a torn snapshot refuses or enters recovery, a mismatch between the discovered writer set and the expected manifest blocks the quiesce transition, and any successful stale-epoch mutation invalidates the rehearsal.
- **`CHECKPOINTED` is defined precisely**, pinning `(aggregate_id, canonical_seq, event-prefix digest, current_writer_epoch, sole writer identity, writer-inventory digest, command-dedup state, snapshot/backup digest, reverse-reader version, parity evidence, crash-matrix evidence, external-effect watermark)`. A post-cutover synthetic local command must demonstrate epoch `E+1` appends exactly the next sequence, retries do not append another event, and epoch `E` is rejected.
- **Projection parity, replay parity, and crash parity are three different gates.** Two event histories can render the same current state while differing in order, duplicates, intermediate states or recovery behavior; output comparison alone (the report's FoundationDB shadow-comparison analogy) proves projection only. The event-prefix digest must cover order, not a set or terminal state.
- **No externally accepted effect is rollbackable in the strong local-state sense.** An accepted SMTP message transfers delivery responsibility; a pushed Git ref mutates remote state; a credential change alters an external authority; a deployment rollback is itself another mutation. Provider idempotency is bounded. After an effect *may* have been accepted, the rule is: preserve the v3 fact, block dependent effects, determine external reality, reconcile forward — never relabel the effect as rolled back.
- **Admission rule:** accept a command only if `aggregate_id` matches, `writer_id == current_owner`, `writer_epoch == current_epoch`, `expected_seq == canonical_seq + 1`, and `command_id` is unseen or an exact retry. The same epoch/sequence check must recur at the durable mutation boundary, not only at an upstream router, because a stale writer can pass a router check and pause before reaching storage.
- **Duplicate-command outcomes:** new ID → execute once and record; same ID with identical payload digest → return the recorded outcome without allocating a sequence; same ID with a different payload → `REFUSED`; any stale-epoch command → `REFUSED`; genuinely unknown commit/effect → query canonical/external reality before retrying, never treat unknown as failure.
- **Writer enumeration must be machine-checkable**, via a generated `writer_manifest` hashed and compared to an explicit allowlist; unknown additions and renames fail closed, and a renamed writer is not silently "the same thing." Negative test: add a synthetic mutation-capable writer and separately rename a known writer; if either reaches the rehearsal without changing the manifest, enumeration is disproven. Out-of-band writes via credentials or direct storage remain unverified until all mutation paths traverse the fenced boundary.
- **Event-sourced strangler migration is useful but insufficient alone:** coexistence is acceptable for reads, replay and shadow verification, but not as two independently writable canonical histories. Expand/contract is retained for adapter/schema compatibility, but generic recipes that write both representations must not become two authoritative writers — either one fenced owner changes both or one is a derived compatibility projection.
- **Saga plus transactional outbox is appropriate only at cross-aggregate boundaries.** A single execution-attempt/lease aggregate should not be split into a saga merely to emulate a transaction; the outbox entry, command identity and local aggregate event must become durable under one owner before asynchronous dispatch.
- **Proof stays per aggregate.** Task lifecycle, assignment persistence, run/evidence, accepted-result ledger and fabric journal each have separate writers and no common monotonic epoch today, so success on the synthetic aggregate cannot be generalized; each needs its own writer inventory and fencing proof, and cross-aggregate changes need explicit saga/outbox boundaries. The fabric-only fixture proves state schema, replay and fault vocabulary only, not the full `OR-015` gate.
- **Rollback before external acceptance is a new ownership transfer:** block commands and fence v3; confirm no post-base effect is `ACCEPTED`/`UNKNOWN`; restore the verified checkpoint at `H` into a non-writable candidate; reverse-read the v3-only suffix exactly once; verify ordered history and projection; allocate epoch `E+2`; reopen ingress. Reverse-reader failure, an unrepresentable v3 event or an ambiguous effect *falsifies rollback eligibility*. A backup existing is not sufficient — restore must be exercised.
- **A five-point deterministic crash matrix applies to every transition:** before prepare, after prepare, during effect, after effect before receipt, after receipt before projection — with fixed seeds and model assistance off. A missing receipt is never treated as evidence the effect did not occur, and reprojection must not re-trigger the effect. The resulting contract is at-least-once attempts plus fenced/idempotent admission and explicit reconciliation, not a universal exactly-once promise.
- **External-effect reconciliation spans five classes** — provider/API submission, pushed Git ref, sent message, credential create/rotate/revoke/change, and deployment/service change — over a state machine of `PREPARED`, `SUBMITTED`, `ACCEPTED`, `REFUSED`, `UNKNOWN`. Unknown is not zero: dependents stay blocked while a prerequisite is `SUBMITTED` or `UNKNOWN`. An inverse action later does not mean the original effect never happened.
- **The recommended cutover boundary is the smallest canonical aggregate plus its mandatory admission/fencing boundary**, with the broker remaining replaceable transport unless a decisive test shows broker offset/ack state is needed for correctness.
- **Mandatory gate defaults:** fixed minimal deterministic scheduling, a fixed bounded retry schedule with stable command IDs, a small fixed fixture volume, all five fault points with fixed seeds, bounded CPU/memory/time, model assistance off, and no external network/effects for the `OR-015` rehearsal; stress/interleaving variants belong in separate configurable lanes.
- **Evidence currency:** the report places AWS's current cloud-pattern set in 2023 (event sourcing added November 2023, strangler updated October 2023, a CDC example added 2024), current Kubernetes resource-version preconditions and FoundationDB simulation/shadow mechanisms in 2025–2026, Git's current push manual (2.55.0 changes dated June 2026), and current PostgreSQL 18 and Prisma consistent-snapshot/staged-migration caveats; SMTP RFC 5321 and OAuth RFC 7009 are retained as normative older standards.
- **Reconciliation classification rule:** for every external-effect class the report separates an authoritative lookup proving rejection/nonexistence from mere absence. A current remote ref is not always decisive because another actor could have moved it after an accepted push; credential revocation can itself have propagation delay; and a deployment rollback does not reverse database writes, messages or credentials produced while the prior revision ran.
- **Completion-gate audit:** the report marks the research deliverable as passing its gate items — writer enumeration defined with a negative falsifier, fencing defined at admission and execution, three parity predicates distinguished, a five-point crash matrix, and external-effect reconciliation for all requested classes — while actual restore execution, implementation and a private secret scan remain outside the authorized research.
- **The fabric-only vs full rehearsal distinction is material:** the state-contract fixture demonstrates state schema, replay and fault vocabulary only, and does not prove complete writer enumeration, stale-epoch exclusion, a real ownership transition, reverse-reader rollback or the full five-point crash matrix across the cutover states.
- **The reservation-ledger boundary is explicit:** the report defines no integer reservation arithmetic, recovery quota algorithm, counter conservation rule or ledger implementation; any such separate aggregate must obey its own writer/fence contract and interact only through a saga/outbox boundary.
- **Critical vs supporting sources:** the report marks etcd distributed locking, AWS transactional outbox, AWS event sourcing and Apache Kafka delivery semantics as critical; FoundationDB simulation and testing-storage-server material, Git's push manual, Kubernetes API concepts and AWS saga guidance as high priority; and PostgreSQL, Stripe, SMTP RFC 5321 and OAuth RFC 7009 as supporting or reference material.
- **Overall classification:** the report labels its freezeable single-writer rule as inferred with high confidence, consistent across the primary evidence on fencing, conditional mutation, event replay, outbox duplicates, failure ambiguity and external-effect semantics.

## Recommendation and falsifier

The report recommends freezing the single-writer contract first on the synthetic execution-attempt/lease aggregate, keeping ownership, canonical sequence, command deduplication and epoch validation inside the aggregate's write-admission/durable-commit boundary, and treating any broker as replaceable transport/outbox rather than canonical truth.

- **Decisive falsifier:** a deterministic experiment that independently crashes, rewinds, duplicates, reorders and replays the broker around cutover. Starting from the same checkpoint, all runs must converge to the same accepted command set, sequence-numbered event history, writer epoch and projection, with duplicate commands returning prior outcomes and stale epochs failing. If any broker offset/acknowledgement value is necessary to prevent a lost or duplicate canonical transition, the recommendation is false and that broker state belongs inside the cutover boundary.
- The competing broker-inclusive design wins only on exactly that showing; the report notes broker idempotence/transactional guarantees have a defined scope and external destinations require cooperation.

## What this does not prove

- Not that the product already has a complete writer inventory, that every storage path can enforce epochs, or that a reverse-reader currently exists — these remain unverified because repository/runtime inspection was prohibited in the public research lane.
- Not that success on the synthetic execution-attempt/lease aggregate generalizes to task lifecycle, assignment persistence, run/evidence, the accepted-result ledger or the fabric journal.
- Not a selection of language, storage engine, provider, authentication or deployment, and not authorization to alter protected state; no live cutover was performed.
- Not a universal exactly-once guarantee, and not proof that any externally accepted effect can be reversed.
- Does not define the numeric recovery-reservation ledger, quota algorithm or counter conservation rules.
