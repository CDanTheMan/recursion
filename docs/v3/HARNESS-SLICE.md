# Recursion harness slice

This fork implements the harness in Python 3.11 or newer under [scripts/v3/harness](../../scripts/v3/harness/run.py). That is the host language. The harness modules use the standard library and call the M1A kernel already in the tree. Route admission loads the M1B checker, which imports `jsonschema` 4.23.0.

Upstream [D-039](../../state/DECISIONS.md) leaves the host language open and points at a language-agnostic outline (open upstream PR 161, not merged here). The M1A and M1B JSON records stay the boundary a later host would reconstruct. The running code in this repository is Python.

## What the existing records already fix

[ARCHITECTURE](ARCHITECTURE.md) ratifies one small deterministic kernel and typed fail-closed adapters (OR-018). Provider sampling, process launch, and frontends stay outside the kernel. Commit and dispatch are separate: a command receipt is not a settled provider effect.

[EXECUTION-FABRIC](EXECUTION-FABRIC.md) keeps kernel admission, broker ownership, and recipient settlement apart. A process exit is one observation. Missing usage is not zero. This slice does not claim settlement.

[ROUTE-CAPABILITIES](ROUTE-CAPABILITIES.md) keeps the route matrix. No live account is certified by the matrix. This slice binds headless commands for Claude Code (`claude -p` with stream-json), Codex (`codex exec --json`), Grok Build (`grok -p` with streaming-json), Gemini CLI (`gemini -p` with stream-json), Cursor CLI (`cursor-agent -p` with stream-json), and OpenCode (`opencode run --format json`). Gemini, Cursor, and OpenCode are disabled in the default config.

[DECISION-REGISTER](DECISION-REGISTER.md) OR-022 requires a native path and an upstream path, with no hidden API key for ordinary upstream use. OR-024 ranks responsiveness, then subscription efficiency, then completion, under correctness and authorization. This slice has no measurement of those rankings.

## Shape

1. **Plan.** [planning.py](../../scripts/v3/harness/planning.py) admits one task through the M1A kernel: owner intent, goal, ARM run, plan, capacity, budget, work packet. The task text is the intent and the goal outcome, and its digest is the task semantic definition. A different task yields a different projection. Record ids are the closed single-task vocabulary; each run is a fresh stream.
2. **Route.** [routing.py](../../scripts/v3/harness/routing.py) loads frozen fixture `F-M1B-001`, validates it, and runs the M1B reference oracle. Execution continues only when the decision status is `selected`. The selected id on that fixture is `route-a`.
3. **Run.** [providers.py](../../scripts/v3/harness/providers.py) is the adapter interface. `fixture` returns a deterministic transcript and starts no process. `claude` argv is `claude -p --output-format stream-json`; the task goes to stdin. `codex` argv is `codex exec --json` plus the task as the prompt argument. `grok` argv is `grok -p`, the task, and `--output-format streaming-json`. `gemini` argv is `gemini -p`, the task, and `--output-format stream-json`. `cursor` argv is `cursor-agent -p --output-format stream-json` plus the task. `opencode` argv is `opencode run --format json` plus the task. A headless process starts only with `--allow-live`.
4. **Choose a provider.** [config/harness.json](../../config/harness.json) lists each provider's command, capabilities, and weight. [capabilities.py](../../scripts/v3/harness/capabilities.py) keeps providers that are enabled and hold every required capability. Higher `routing.weights` run first. Equal weights keep preference order. That choice is not an M1B route id. [dispatch.py](../../scripts/v3/harness/dispatch.py) skips a provider in cooldown, retries a transient error or a timeout with backoff, and on a rate limit, exhausted quota, or expired auth records a cooldown and tries the next capable provider. A failed attempt records the error class. Provider stderr is not copied into the error, the log, or the cooldown file.
5. **Entry point.** [scripts/recursion](../../scripts/recursion) is the terminal command. `plan` admits the task and the route. `run` then executes. `status` prints the config, a JSONL log summary, and saved runs. `resume` continues a saved run. `cancel` stops unfinished tasks. `providers` prints each configured provider, whether its command resolves, its capabilities, and its cooldown. It uses the same PATH search as `doctor`, including Windows `.cmd` and `.exe` shims, and it does not start a CLI or probe sign-in. `doctor` reports whether git is available, whether Windows `core.longpaths` is on, and for each provider whether its executable resolves, its version, and a cheap sign-in check when one exists. It exits non-zero when no enabled provider is usable. `init` writes a starter config to a given path, refuses to overwrite it without `--force`, and enables the providers doctor can see. [log.py](../../scripts/v3/harness/log.py) writes one JSON object per event. When stderr is a terminal, or when `run` or `resume` is passed `--progress`, stderr gets a plain progress line instead and the JSONL stream stays on `--log`. Sign-in checks do not print tokens.
6. **Several tasks.** [dag.py](../../scripts/v3/harness/dag.py) asks a capable provider for a JSON task list with ids, descriptions, required capabilities, and `depends_on`. The prompt includes an example where `test` depends on `build`. The list is checked for shape, unique ids, known dependencies, and cycles. Invalid output falls back to one task per non-empty line, and the log records why. A fixture goal whose first line is `graph` returns a real dependency list instead of that line split. Each description is still a separate M1A admission. Tasks run only after their dependencies have landed, up to `orchestration.concurrency`. `run` and `resume` accept `--concurrency N` (an integer `>= 1`) to override that value for one invocation. The effective value is stored on the run. Resume without the flag keeps the stored value. A failed or rejected dependency marks dependents skipped. `recursion plan` prints the graph. The planning prompt also includes a size-capped repository map: the tracked file tree and the opening text of `README.md`, `docs/USER-GUIDE.md`, and `docs/v3/START-HERE.md` when those files exist. A dependent task's prompt includes a size-capped summary, commit, and diff for each task it depends on. Token-shaped text in that context is redacted. Run records live under `.recursion/runs` ([state.py](../../scripts/v3/harness/state.py)). `recursion land <run-id>` merges a finished run branch into the current branch, or into `--into`, with a non-fast-forward merge. A dirty worktree or a conflict is refused and recorded on the report. `recursion clean` removes run records, reports, logs, worktrees, and task and run branches older than `--older-than` days (default 7). `--dry-run` lists them without deleting. A branch checked out in the main worktree is left in place.
7. **Provider limits.** Each provider has `timeout_seconds`. A missing executable names the command and does not dump stderr. [availability.py](../../scripts/v3/harness/availability.py) classifies auth, quota, rate limit, and transient failures from the exit code and the error text for every headless adapter. [cooldowns.py](../../scripts/v3/harness/cooldowns.py) stores the reason and reset time in `<state-dir>/cooldowns.json` so later tasks and later runs skip that provider. A reported reset time is kept. Otherwise the cooldown is `routing.cooldown_seconds`. Transient errors and timeouts wait `backoff_seconds * (attempt + 1)` before another try of the same provider. Cancel and timeout both stop the live process and the children it started: a new process group on Linux, a job object on Windows. The driver notices a stored cancel while that process is still running.
8. **Install.** [pyproject.toml](../../pyproject.toml) exposes the `recursion` console script. `python -m pip install -e .` works on Windows and Linux. The checkout command `python -X utf8 -B scripts/recursion` still runs without install.
9. **Isolation.** [isolation.py](../../scripts/v3/harness/isolation.py) gives each task its own git worktree and branch, `recursion/task/<run-id>/task-<index>`, cut from the run branch `recursion/run/<run-id>`. The run branch is cut from `landing.base_ref` (default `HEAD`). Uncommitted edits are committed when the provider did not commit them. Accepted branches are merged into the run branch. A merge conflict is recorded on that task and the merge is aborted. Unreviewed branches are kept and are not merged. Failed and rejected branches are deleted unless `--keep-worktrees` is set. The task namespace is separate from the run branch so git can store both refs.
10. **Review.** [review.py](../../scripts/v3/harness/review.py) asks a different capable provider to read the diff and the output. The first non-empty line must be `VERDICT approve` or `VERDICT revise`. A revise sends the notes back to the same worker, for at most `review.max_rounds` rounds in [config/harness.json](../../config/harness.json). Verdicts are stored on the task. An unreadable review is a revise and the raw body is not stored. Reviewer edits to the worktree are removed and rejected. If no reviewer finishes, `review.accept_unreviewed` decides the result. The default records the task as `unreviewed`. Failed review attempts are stored on that verdict.
11. **Report.** [report.py](../../scripts/v3/harness/report.py) writes `<run-id>.report.json` and `<run-id>.report.md` next to the run record. Each task lists its diff, provider, attempts, review verdicts, duration, branch, and commit. The report also names the run branch.
12. **Usage and budgets.** [usage.py](../../scripts/v3/harness/usage.py) reads token and cost figures when a provider stream includes them. Gemini `result.stats`, Cursor `result.usage`, and OpenCode `step_finish` tokens and cost are included. [streams.py](../../scripts/v3/harness/streams.py) separates assistant text from tool output for those three. A missing figure stays unknown. `budgets.max_input_tokens`, `budgets.max_output_tokens`, and `budgets.max_cost` stop the run when a known figure is above its ceiling. `null` means no ceiling.

The planning route id `ROUTE-INCLUDED` and the M1B id `route-a` are different namespaces. This slice does not alias them. The adapter runs only after M1B selection succeeds.

## Gate

`python -X utf8 -B tools/check_v3_orientation.py --contracts` runs the original 23 M1 programs, [harness.test.py](../../scripts/tests/v3/harness/harness.test.py), [adapters.test.py](../../scripts/tests/v3/harness/adapters.test.py), [doctor.test.py](../../scripts/tests/v3/harness/doctor.test.py), [landing.test.py](../../scripts/tests/v3/harness/landing.test.py), [live.test.py](../../scripts/tests/v3/harness/live.test.py), [ops.test.py](../../scripts/tests/v3/harness/ops.test.py), [orchestration.test.py](../../scripts/tests/v3/harness/orchestration.test.py), [progress.test.py](../../scripts/tests/v3/harness/progress.test.py), [review.test.py](../../scripts/tests/v3/harness/review.test.py), [routing.test.py](../../scripts/tests/v3/harness/routing.test.py), and [streams.test.py](../../scripts/tests/v3/harness/streams.test.py). The 2026-09-13 path freeze no longer describes this tree, so the gate keeps that commit as an ancestor, checks orientation invariants, and rejects untracked files outside this slice. It does not fail the repository for later research paths already on the branch.

## Out of this slice

Worker-result and gate-result admission, and durable projection storage. Live provider calls stay out of CI. [live.test.py](../../scripts/tests/v3/harness/live.test.py) runs only when `RECURSION_LIVE=1`, the provider CLI is on PATH, and neither `CI` nor `GITHUB_ACTIONS` is set.
